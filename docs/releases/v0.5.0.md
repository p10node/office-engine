## Update a style to match the selection

- docx: right-click → **Update style to match** → a style (Normal text, Title, Subtitle, Heading 1–6, the document's other quick styles). The style takes the look of the selection — font, size, colour, bold, italic, underline, strikethrough, alignment, line and paragraph spacing — and every paragraph of that style, and of the styles based on it, follows: headings, headers and footers, list numbers included. The selected paragraphs get the style and stop carrying that formatting themselves, so the next update reaches them too.
- The look is written to the document's own styles part only, as what differs from the style it is based on; theme fonts and colours the file came with stay tied to the theme. Nothing outside the file changes.
- Undo takes the style back as it was, down to the byte, and the text back to the formatting it had been given.
- Shared rooms: everyone sees the new look, those who join later too. Text a collaborator typed before the change reached them is shown with the new look as well.
- From a table cell, what the table style adds (its spacing, a header row's bold) stays out of the paragraph style.
- Context menus can hold submenus (keyboard: → opens, ← / Esc closes).

Known limits: paragraphs inside nested tables and text boxes take the new look when the document is reopened; highlight, indentation and list settings are not part of the look.

For integrators: `RunSet` and `ParaDirty` (direct formatting) accept `null` for a property, which drops the paragraph's or run's own setting; new worker methods `docx.styleSet` and `docx.convert`; new types `StyleLook`, `StyleSetResult`, `HeaderFooters`.
