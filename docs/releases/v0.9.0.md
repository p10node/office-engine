## Diagrams: Mermaid, PlantUML, Graphviz

- `.mmd` / `.mermaid` (Mermaid), `.puml` / `.plantuml` / `.pu` / `.iuml` / `.wsd` (PlantUML) and `.dot` / `.gv` (Graphviz) open as a document holding the drawing, from any `src` and from File → Open. The bar shows an `MMD`, `PUML` or `DOT` badge; saving writes a `.docx` with the drawing as an SVG picture, scaled to the page (a wide one gets a landscape page).
- Diagram code blocks are drawn in place: ` ```mermaid `, ` ```plantuml ` / ` ```puml `, ` ```dot ` / ` ```graphviz ` in Markdown, and `<pre class="mermaid">`, `<div class="mermaid">`, `<pre><code class="language-…">` in HTML. Other code blocks stay code.
- What is drawn:
  - Mermaid: flowchart / graph (subgraphs, `classDef`, `style`, `linkStyle`), sequence, class, state, ER, pie, Gantt, mind map
  - PlantUML: sequence, class / object, use case, component / deployment, state, activity (new syntax), mind map, WBS, `@startdot`; a file with several diagrams draws them all
  - Graphviz: graph / digraph, clusters, default attributes, edge chains, `rank=same`, shapes, styles and colors, record and HTML labels (as text)
- Drawn in the worker by a built-in renderer with a layered layout (like Mermaid's and Graphviz's `dot`): no server, no network request, no new dependency. Drawings look close to, not exactly like, the original tools'.
- A diagram that cannot be drawn (other Mermaid kinds such as git graph or journey, PlantUML Gantt or JSON…) shows why, followed by its source.
- The format comes from the extension, else the MIME type, else the content (`@startuml`, `digraph {`, a Mermaid header), also for a Blob or URL served as `text/plain`. A binary `.dot` (a Word 97 template) is not read as a graph.
- The pictures are safe: the text is escaped, only plain colors are kept, and the SVG has no scripts, links or external references.

## Code side by side

- Markdown, HTML and diagram files get a **Code** button: the source shows next to the document, with line numbers and syntax colors (diagram blocks in Markdown in their own language). Edit it and the document is built again as you type; the page keeps its scroll position and the previous version stays until the new one is ready.
- While the source is shown, the document is a preview (the source is what is edited). Save (also `Ctrl/⌘+S` in the source) writes the Word file; the source pane copies the source or downloads it as `.md`, `.mmd`…
- The divider can be dragged or moved with the arrow keys; in a narrow viewer the source goes above the document.
- File → Open of a CSV, text, Markdown, HTML or diagram file now goes through the worker like a `src`: the bar keeps the file's own name (`notes.md`, was `notes.docx`); saving still writes `notes.docx`.

## Standalone packages

The renderers ship on their own, to show diagrams and Markdown in any page without the viewer (no DOM needed, works in a worker or Node, no dependency):

| Package             | For                                                                                        | Size (gzip) |
|---------------------|--------------------------------------------------------------------------------------------|-------------|
| `@p10node/diagram`  | Mermaid, PlantUML and Graphviz; `renderPage()` draws a page's diagram blocks               | 37 KB       |
| `@p10node/mermaid`  | Mermaid → SVG                                                                              | 26 KB       |
| `@p10node/plantuml` | PlantUML → SVG (no Java)                                                                   | 29 KB       |
| `@p10node/graphviz` | Graphviz DOT → SVG (no WebAssembly)                                                        | 16 KB       |
| `@p10node/markdown` | Markdown → safe HTML (CommonMark, GitHub tables and task lists), diagram code blocks drawn | 39 KB       |

Each has `render()` → `{ svg, width, height }`, `renderTo(element, …)` and (diagrams) `toPng(svg)`. They are released with `@p10node/office-engine`, at the same version.

For integrators: `OpenResult.imported` can also be `'mermaid'`, `'plantuml'` or `'graphviz'`. New worker method `plain.source` (the text of a Markdown / HTML / diagram file). The worker bundle is about 125 KB larger (the diagram renderer); the main-thread bundle carries only the source editor.
