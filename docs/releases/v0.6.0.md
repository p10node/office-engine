## Comments

- Comments on DOCX text, XLSX cells and PPTX slides: threads with replies, resolve / reopen, edit and delete your own, @mentions. Start one with `Ctrl/⌘+Alt+M`, right-click → Comment, or the Comments panel (bar button → New comment).
- The panel lists the threads in document order with what they point at (commented text, `Sheet1!B3`, `Slide 2`); resolved threads on demand. Commented text is highlighted, cells get a corner mark, slides a pin; clicking them shows the thread.
- Stored in the file the way Office stores them, so Word, Excel and PowerPoint show them, and comments from Office files show here: DOCX `comments.xml` + extended / ids / extensible / people parts; XLSX threaded comments + persons, with the legacy comment and VML Excel keeps next to them (notes are read as one-comment threads and stay notes while untouched); PPTX modern comments + authors (legacy comments are read, and written back as modern ones). Ids survive saving and reopening; so do mentions (XLSX natively, DOCX / PPTX through the people / authors list).
- DOCX ranges follow the text: typing inside extends them, typing right after does not, undo takes a new comment away; a thread whose text is deleted leaves the file. XLSX threads move with inserted / deleted rows and columns. PPTX threads stay with their slide.
- Shared rooms: comments are shared operations; everyone sees them live, newcomers get them from the file or the history.

For integrators: new `comments` prop (`user`, `mentions`, `canComment`, `onEvent`, `open`, `focus` — a thread to show on open; `false` hides comments), `<office-viewer comments="false">` and its `comment` event. `onEvent` reports the changes made in this viewer with who was mentioned and who else wrote in the thread, for host notifications. Worker methods `comments.list` / `comments.set` and event `comment`; types `DocComment`, `CommentUser`, `CommentEvent`, `CommentOptions`; `threadsOf`. DOCX runs carry `cm` (thread ids) in the paragraph model.
