## Word: tables, page setup, headers and footers, tracked changes

- **Tables**: select cells by dragging across them; merge and unmerge (across and down, text kept in reading order); cell color (also "No fill" over a table style), cell borders (all / outer / inner / none / one side, color and line style), vertical alignment, distribute columns evenly, drag a column edge to resize. Written as the cell's own properties, so Word shows the same.
- **Page setup** (toolbar): paper size (A4, Letter, Legal, A3, A5, B5), portrait / landscape, margins in cm with presets, 1 to 3 text columns with spacing. It applies to the whole document, and columns are laid out on screen too.
- **Headers and footers**: double-click a page's header / footer area, or use the toolbar. Header, footer and first-page parts, alignment, bold, size, page number and page count fields with presets ("Page 1 of 5", "Trang 1/5"), different first page. A part holding pictures or tables warns that editing replaces them.
- **Tracked changes**: insertions and deletions made in Word show in their author's color (hover shows who and when) and are kept on save. Before, editing a paragraph silently accepted its changes. Review: next / previous change, accept or reject the change at the caret, the selection, or all of them (one undo step). *Track changes* records your own edits as suggestions (typing, deleting, pasting, replacing), signed with the comments / collaboration user. Deleted text is left out of the text export, the word count and the outline.
- All of these are undoable and shared in collaboration rooms, late joiners included.

Known limits: formatting changes, paragraph marks and objects are not recorded as suggestions; moved text is written back as a plain insertion and deletion.

## CSV, text, Markdown and HTML as `src`

- `.csv` / `.tsv` open as a workbook and `.txt` / `.md` / `.html` as a document from any `src` (File, Blob, ArrayBuffer, URL), from drag & drop in the demo, and from File → Open. Before, only File → Open converted them; a CSV passed as `src` failed with "Not a ZIP". The worker converts them, they are editable, and saving writes `.xlsx` / `.docx`. *Download as* CSV / text / Markdown gives the plain format back.
- The format comes from the extension (of `name`, the File or the URL), else the MIME type (Blob type, `Content-Type`), else the content (HTML, delimited rows, or text). A name ending in `.docx`, `.xlsx`, `.pages`… is always read as a package.
- Text encodings: byte order mark (UTF-8, UTF-16), the declared charset, UTF-8, else Windows-1252 (Excel's CSV export on Windows). File → Open reads them too; before, it read UTF-8 only.
- The bar shows a `CSV`, `TSV`, `TXT`, `MD` or `HTML` badge. Document details says what the file was, e.g. "CSV file, opened as Excel workbook".
- The demo has `sample.csv` and `sample.md`.

For integrators: `OpenResult.imported` (`client.info.imported`) is `'csv'`, `'tsv'`, `'text'`, `'markdown'` or `'html'` for a converted plain file, which stays editable (unlike `from`). `ByteSource.type` holds the MIME type when known. New worker methods `docx.page` (page setup) and `docx.hf` (headers / footers), with types `PageSet`, `PageSetResult`, `HFSet`, `HFSetResult`. The worker bundle is about 27 KB larger (the HTML reader and the converters).
