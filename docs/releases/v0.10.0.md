## CSV: no row limit

- **Streamed in**: a `.csv` / `.tsv` (as `src`, from File → Open or dropped on the demo) no longer becomes a string, a table of strings and a workbook XML before it shows. The bytes are read in chunks in the worker and the rows go straight into the sheet's model, the way a worksheet's XML does: the first rows show at once and the rest streams in like a large workbook's. A million rows × 10 columns (99 MB) open in about 2.4 s. Column widths come from the first 5,000 rows.
- **Rows past memory stay in the file**: past 12 million cells (about 300 MB in Chrome) the loader notes where each page of 1,024 rows starts and goes on counting; a page is read from the file when its rows are shown, edited, searched, exported or saved, the least recently shown pages making room (pages with edits stay). So there is no row limit: 25 million rows (2.7 GB) open in ~14 s and 100 million rows × 10 columns (10.6 GB) in ~50 s in Chrome, the tab staying at about 1 GB of memory either way. Scrolling, jump to the last row, find and replace, sort, cell edits and formulas all work on such a sheet.
- Limits of a paged sheet: rows and columns cannot be inserted or deleted, and an edit or a formula may only need the rows that fit in memory (`=SUM(A:A)` over 100 million rows is refused with a message; a formula reading a row that is not in memory shows `#VALUE!`).
- **Excel's row limit**: a sheet of more than 1,048,576 rows cannot be saved as a workbook. The bar says so, Save fails with a message, and *Download as* CSV / TSV gives the rows, written in the worker page by page. A comma file starts with a byte order mark, so Excel reads it as UTF-8.
- Encodings as before: byte order mark (UTF-8, UTF-16 LE / BE), the declared charset, UTF-8, else Windows-1252 (the rows read so far are dropped and read again). The file can be cut anywhere between chunks: inside a quoted field, a CRLF, a multi-byte character.
- **File → Import CSV into new sheet** streams the file the same way into a sheet after the current one, named after the file. In a shared session the rows reach everyone as cell edits.
- The samples script writes a million-row `large-rows.csv`; `bun scripts/large-csv.ts 25000000 out.csv` writes a larger one for load tests (`large-*` samples are not committed).

## Fixes

- Diagrams: an edge that passes layout dummies (a long or labelled edge) is drawn as one smooth curve, square-on at both ports. Before, each piece was its own S-curve, so a dummy next to an end put the whole bend into a short piece, and an arrowhead trimmed on such a piece could fold the curve back on itself.

For integrators: new worker methods `xlsx.import(after, src, { name?, sep?, residentCells?, pageRows? })` (a new sheet holding a CSV / TSV, streamed in when the sheet loads) and `xlsx.text(sheet, sep)` (the sheet as CSV or TSV, a Blob, since it can be larger than a string should be). Open parameters `residentCells` (default 12,000,000) and `pageRows` (default 1,024) set the memory budget and the page size for CSV / TSV. `xlsx.block` on a paged sheet reads its pages from the file first, so a block far down takes a file read. The worker bundle is about 19 KB larger (6 KB gzipped).
